Interface & Parâmetros SX1 • MV_PAR

SX1: Grupos de Perguntas (A Tecla F12 das Telas)

O SX1 armazena os parâmetros de filtro que o usuário preenche antes de rodar relatórios ou rotinas de processamento. Quando o usuário abre uma rotina e clica em Outras Ações -> Parâmetros (ou pressiona F12), o Protheus lê a tabela SX1 e desenha a tela de perguntas dinamicamente.

🎯 Como Ler Perguntas no Código ADVPL:

No código, o Protheus cria variáveis públicas automáticas chamadas MV_PAR01, MV_PAR02, etc., de acordo com a ordem das perguntas cadastradas.

🛠️ Função de Carregamento:

Utiliza-se a função nativa Pergunte("NOME_GRUPO", .T.) para forçar a abertura da janela de perguntas antes de iniciar a execução da rotina.

// Exemplo de uso de SX1 em código corporativo:
If Pergunte("MTR410", .T.) // .T. abre a janela para o operador preencher
    cClienteDe := MV_PAR01 // Pergunta 01: Do Cliente?
    cClienteAte := MV_PAR02 // Pergunta 02: Até o Cliente?
EndIf
Estrutura de Banco SX2 • RetSqlName()

SX2: Cadastro das Tabelas e Arquitetura Multi-Empresa

O SX2 é a tabela que registra todas as entidades do ERP. É nela que o Protheus sabe se a tabela SA1 (Clientes) é Compartilhada entre todas as empresas do grupo ou Exclusiva por filial.
🔍
Por que o Banco Real tem Tabelas como SA1010 ou SA1020?

O Protheus concatena o Alias de 3 letras da tabela com o código da Empresa. Se a sua empresa for a 01, a tabela física criada no SQL Server / Oracle é SA1010. Por isso, NUNCA faça SELECT * FROM SA1 direto no SQL! O código correto em ADVPL deve sempre chamar RetSqlName("SA1") para descobrir dinamicamente o nome físico correto!

Metadados de Colunas SX3 • X3_VALID

SX3: Dicionário de Campos e Validações de Sistema

Cada coluna de qualquer tabela do Protheus é registrada no SX3. O SX3 define o tipo do dado (C, N, D, M), a quantidade de caracteres, as casas decimais, a máscara de exibição (Picture) e a regra de validação que o sistema executa automaticamente ao digitar no campo.

🛡️ X3_VALID (Validação de Usuário)

Fórmula ou chamada de função executada no momento em que o operador sai do campo. Se retornar .F., o cursor é travado e o Protheus exibe um Help de erro.

🔄 X3_RELACAO (Gatilho ou Inicializador)

Expressão avaliada para preencher o valor padrão do campo no momento da inclusão (ex: dDataBase para preencher a data de hoje).

Performance de Banco SIX • DbSetOrder() • DbSeek()

SIX: Índices do Banco de Dados e Busca Rápida

A tabela SIX armazena os índices de todas as tabelas. Para buscar dados em milissegundos sem sobrecarregar o banco, utilizamos a ordem do índice (DbSetOrder) combinada com a busca binária (DbSeek).
// Exemplo de busca de alta performance por índice:
DbSelectArea("SA1")
DbSetOrder(1) // Índice 1: Filial + Código + Loja (A1_FILIAL + A1_COD + A1_LOJA)

If DbSeek(xFilial("SA1") + "000001" + "01")
    ApMsgInfo("Cliente localizado: " + SA1->A1_NOME)
EndIf

Módulo 1: Fundamentos 01_Variaveis.prw

Capítulo 01: Anatomia de um Fonte ADVPL & Gestão de Memória

O primeiro passo para se tornar um desenvolvedor TOTVS profissional é entender como o compilador do Protheus enxerga seu código. Um arquivo .prw é pré-processado, compilado em bytecode e armazenado no repositório de objetos (RPO).

📦 1. O Cabeçalho #Include "Totvs.ch"

Instrui o pré-processador a traduzir constantes do ERP antes da compilação. Sem ele, comandos fundamentais como CRLF e definições visuais não funcionam.

🏷️ 2. A Notação Húngara Oficial

O tipo da variável é identificado pela primeira letra: c (Character), n (Numeric), d (Date), l (Logical), a (Array) e b (Codeblock).

💡
Regra de Ouro dos Escopos (Por que 95% do seu código deve ser Local)

Variáveis Local residem exclusivamente na pilha da função e são destruídas da memória RAM assim que a rotina encerra. Evite Private e Public para não vazar memória no AppServer!

Módulo 1: Fundamentos 02_Logica.prw

Capítulo 02: Engenharia de Fluxo, Arrays Dinâmicos & Static Functions

Avanço na tomada de decisão corporativa: a diferença entre If...ElseIf e Do Case, manipulação dinâmica com aAdd() e isolamento com Static Functions.
⚠️
O Erro Fatal: "Duplicated function found in RPO"

Funções auxiliares internas devem SEMPRE ser declaradas como Static Function. Isso impede que dois arquivos tenham funções com o mesmo nome colidindo no RPO.

Módulo 1: Fundamentos 02B_Loops.prw

Capítulo 02B: Estruturas de Repetição (Loops) & Prevenção de Travamento

O domínio dos laços de repetição é vital para processar matrizes, relatórios e tabelas no Protheus. Entenda a diferença crítica entre o laço pré-condicional While...EndDo e o laço determinístico For...Next, além do uso de Exit (break) e Loop (continue).

🔄 1. While...EndDo (Laço Pré-Condicional)

Executa enquanto a expressão for verdadeira. No Protheus, todo laço While deve conter obrigatoriamente o avanço da variável de controle (ex: nI++ ou DbSkip()), caso contrário gerará loop infinito e travará o AppServer!

🛑 2. For...Next com Exit e Loop

O comando Exit interrompe imediatamente o laço (útil para buscas quando o item já foi encontrado). Já o comando Loop pula o restante da iteração atual e avança direto para o próximo passo.

🚨
Regra Crítica de Performance: Evite cálculos pesados dentro do laço!

Funções como Len(aVetor) não devem ser chamadas a cada passo do laço. Guarde o total antes em uma variável: nTam := Len(aVetor) para economizar milhares de ciclos de CPU em grandes matrizes.

Nível 2: Banco de Dados 06_BancoDeDados.prw

Capítulo 06: Consultas SQL no ERP Protheus (TopConnect & TCQuery)

Este é o ponto de virada na sua formação como desenvolvedor TOTVS: conectar seu código ao banco de dados relacional. Até a Aula 05, trabalhamos apenas com dados na memória RAM do computador. Agora, aprendemos a ler tabelas reais do ERP (como a SA1 - Cadastro de Clientes) de forma profissional, segura e compatível com qualquer banco do mercado.

🛡️ 1. GetNextAlias() — Áreas de Trabalho Seguras

No Protheus, cada consulta SQL cria um "cursor" na memória. Nunca use nomes fixos como "TRB", pois se dois usuários rodarem a rotina ao mesmo tempo, um sobrescreverá o outro. GetNextAlias() gera um identificador único e à prova de concorrência.

🏢 2. RetSqlName("SA1") — A Chave Multi-Empresa

O Protheus não cria uma tabela chamada apenas SA1 no banco. Ele concatena o código da empresa física (ex: SA1010). Usar RetSqlName("SA1") é a única forma oficial de garantir que seu código funcione em qualquer cliente ou filial.

🗑️ 3. O Campo D_E_L_E_T_ (Deleção Lógica)

No ERP Protheus, quando um usuário exclui um registro, o registro NÃO é apagado do banco! Ele apenas recebe um asterisco * no campo D_E_L_E_T_. Por isso, toda query no Protheus é obrigada a conter: WHERE D_E_L_E_T_ = ' '.

🔄 4. O Ciclo de Leitura: While !(cAlias)->(Eof())

O cursor do banco é lido linha por linha. O comando (cAlias)->(DbSkip()) avança para o próximo registro, e a função (cAlias)->(Eof()) detecta quando chegamos ao fim da lista.

🚨
Regra de Ouro da TOTVS: Sempre fechar a área com DbCloseArea()!

Toda vez que você abrir uma consulta com TCQuery, você é estritamente obrigado a fechá-la no final do fonte com (cAlias)->(DbCloseArea()). Se esquecer essa linha, o cursor permanecerá aberto no DBAccess, consumindo licenças e esgotando a memória do servidor!

// Como consultar o banco de dados e ler linha a linha de forma profissional: #Include "Totvs.ch" #Include "TopConn.ch" Local cQuery := "SELECT A1_COD, A1_NOME FROM " + RetSqlName("SA1") + " WHERE D_E_L_E_T_ = ' '" TCQuery ChangeQuery(cQuery) New Alias "QRY_CLI" While !QRY_CLI->(Eof()) ConOut("Cliente: " + QRY_CLI->A1_NOME) QRY_CLI->(DbSkip()) // Pula para o próximo registro EndDo QRY_CLI->(DbCloseArea()) // Libera a memória do servidor
Nível 2: Customizações Oficiais 07_PontosDeEntrada.prw

Capítulo 07: Pontos de Entrada & Hooks do ERP (GetArea, RestArea & MT410OK)

Os Pontos de Entrada (PEs) são ganchos oficiais (hooks) disponibilizados pela TOTVS dentro das rotinas padrões do ERP. Eles permitem injetar regras de negócio customizadas sem alterar uma única linha do código fonte padrão da TOTVS, garantindo que atualizações de release não sobrescrevam suas regras.

🛡️ 1. GetArea() e RestArea() — Lei Suprema

Em 100% dos Pontos de Entrada é obrigatório salvar a área ativa com Local aArea := GetArea() na primeira linha e restaurar com RestArea(aArea) antes do Return. Esquecer isso desposiciona tabelas e corrompe dados em produção.

🎯 2. O Contrato de Retorno do PE

PEs de validação esperam retorno lógico: .T. permite que a gravação continue, enquanto .F. bloqueia a operação e cancela a transação no ERP.

🛑 3. Mensagens com Help() em vez de ApMsgInfo

Em PEs de validação de tela, nunca use ApMsgInfo() simples se houver transação aberta. Utilize Help() para registrar a mensagem no dicionário de Help do Protheus sem gerar deadlocks.

🔍 4. ExistBlock() e ExecBlock()

O Protheus verifica a existência de um PE com ExistBlock("NOME_PE") e o executa dinamicamente com ExecBlock("NOME_PE", .F., .F., aParametros).

💡
Exemplo Real: Bloqueio de Pedidos no Ponto de Entrada MT410OK

No faturamento (MATA410), ao confirmar o pedido de venda, o Protheus invoca MT410OK(). Se o valor do pedido ultrapassar R$ 50.000 ou o cliente estiver inadimplente, retornamos .F. com uma explicação para o operador.

// Padrão de Ponto de Entrada Seguro (Conformidade CodeAnalysis / SonarQube): User Function MT410OK() Local aArea := GetArea() Local lRetorno := .T. If SC5->C5_VLRTOT > 50000 lRetorno := .F. Help("", 1, "MT410OK",, "Pedidos acima de R$ 50.000 requerem aprovacao gerencial.", 1, 0) EndIf RestArea(aArea) Return lRetorno
Nível 2: Dicionário & Configurações 08_Parametros.prw

Capítulo 08: Parâmetros Globais do ERP (Tabela SX6, GetMV & PutMV)

No Protheus, desenvolvedores profissionais nunca deixam regras fixas no código (hard-coded). Valores de tolerância, e-mails de alerta, alçadas de desconto e integrações devem ser configurados em parâmetros na Tabela SX6 e lidos dinamicamente com GetMV().

⚙️ 1. GetMV("MV_NOME") — Leitura Transparente

Lê o valor do parâmetro considerando o contexto de empresa e filial ativo. O retorno assume automaticamente o tipo do parâmetro (Caractere, Numérico, Lógico ou Data).

✏️ 2. PutMV("MV_NOME", xValor) — Gravação

Grava ou atualiza o conteúdo do parâmetro na tabela SX6. Deve ser usado com cautela para não alterar parametrizações globais de outros departamentos.

🏢 3. Parâmetros por Filial vs Compartilhados

No Configurador (SIGACFG), parâmetros podem ser configurados com conteúdo exclusivo por filial (X6_FIL == cFilAnt) ou genéricos com filial em branco.

🚀 4. Performance e Cache do SX6

O AppServer mantém em cache de memória os parâmetros mais acessados. Ler com GetMV() é extremamente veloz e não sobrecarrega o banco de dados.

// Exemplo prático de eliminação de Hard-code usando SX6: Local nLimitePedido := GetMV("MV_LIMPED") // Lê valor da SX6 (ex: 50000.00) Local nDescMaximo := GetMV("MV_PERDESC") // Percentual max de desconto (ex: 15.0) If nDescontoDado > nDescMaximo ApMsgStop("Desconto acima do permitido pelo parametro MV_PERDESC!", "Bloqueio") EndIf

🎯 As 3 Perguntas Mais Feitas em Entrevistas para Desenvolvedor Protheus:

1. "Qual é a diferença entre variável Local e Private no Protheus?"

Resposta Ideal: A variável Local é visível exclusivamente na função onde foi criada e é liberada da RAM ao sair. A variável Private é herdada por todas as funções filhas chamadas a partir daquela rotina, podendo gerar efeitos colaterais e vazamento de memória se não for bem controlada.

2. "Como você customiza uma regra de negócio num Pedido de Venda sem alterar o fonte padrão da TOTVS?"

Resposta Ideal: Através de Pontos de Entrada (PEs) oficiais disponibilizados pela TOTVS, como o M410LIOK (para validação de linha) ou M410TUDO (para validação do pedido completo), compilando o fonte customizado no RPO do cliente.

3. "Por que não devemos fazer consultas SQL diretas usando SELECT * FROM SA1?"

Resposta Ideal: Porque o Protheus trabalha com arquitetura multi-empresa e multi-filial onde a tabela física no banco recebe o sufixo da empresa (ex: SA1010). O correto é usar RetSqlName("SA1") e filtrar sempre pela filial ativa com xFilial("SA1").
